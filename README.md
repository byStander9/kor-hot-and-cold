# 한국어 Hot and Cold

[![CI](https://github.com/byStander9/kor-hot-and-cold/actions/workflows/ci.yml/badge.svg)](https://github.com/byStander9/kor-hot-and-cold/actions/workflows/ci.yml)

비밀 단어와 의미적으로 가까운 한국어 단어를 추측하며 정답을 찾아가는 게임입니다. 각 추측은 원시 유사도 대신 **전체 후보 어휘 중 의미 근접 순위**로 표시합니다. 숫자 시드를 공유하면 누구나 같은 문제로 경쟁할 수 있고, 랜덤 시드로 새 게임을 계속 만들 수 있습니다.

> 현재 상태: 공개 데이터 기반 웹 MVP와 Android 우선 Expo 모바일 MVP가 완성되었습니다. 280,804개 표제어와 577,999개 활용형 별칭을 제공하며, 32비트 시드 약 42억 개가 전체 표제어 중 정답을 결정합니다. Play 스토어 배포 전 Android 실기기 플레이 테스트와 운영 API 배포는 남아 있습니다.

## 왜 만드는가

Reddit의 Hot and Cold를 플레이한 뒤 같은 탐색의 재미를 한국어로도 자연스럽게 구현하고 싶어 시작했습니다. 단순 번역이 아니라 다음 한국어 특성을 제대로 처리하는 것이 목표입니다.

- 조사와 어미가 붙은 입력
- 동사·형용사의 다양한 활용형
- 띄어쓰기와 표기 변형
- 동음이의어와 다의어
- 실제 한국어 화자가 납득할 수 있는 근접 단어 순위

## 게임 방식

1. 주소의 숫자 시드가 비밀 단어 하나를 정합니다.
2. 관련 있다고 생각하는 단어를 입력합니다.
3. 비밀 단어와 가까운 순위를 확인합니다.
4. 더 가까운 단어를 따라가며 1위인 정답을 찾습니다.
5. 같은 시드를 친구에게 공유하거나 랜덤 시드로 다음 게임을 시작합니다.

분포 기반 언어 모델에서는 반의어도 같은 문맥에서 자주 등장하기 때문에 서로 가깝게 나올 수 있습니다. 이 특성도 게임 규칙의 일부로 설명할 예정입니다.

## 개발 원칙

- 화면보다 데이터와 순위 품질을 먼저 검증합니다.
- 공개 데이터와 공개 모델을 우선 사용합니다.
- 사용한 모든 자료의 출처, 버전, 라이선스를 기록합니다.
- 원천 데이터의 재배포 조건이 불명확하면 저장소에 포함하지 않습니다.
- 요청마다 유료 AI API를 호출하지 않고 공개 모델로 미리 만든 임베딩을 사용합니다.
- 기능 하나가 검증될 때마다 독립된 커밋으로 공개합니다.

## 기술 구성

- 웹: Next.js, React, TypeScript
- 모바일: Expo SDK 54, React Native, Expo Router, TypeScript
- 데이터 파이프라인: Python
- 공개 모델·데이터 탐색: Hugging Face Hub
- 형태소 처리: Kiwi/kiwipiepy 오프라인 별칭 생성
- 유사도 모델: `intfloat/multilingual-e5-small`
- 테스트: Vitest, Playwright, Expo Doctor, pytest, GitHub Actions

| Hugging Face multilingual-e5-small | 뜻풀이 기반 의미 벡터와 전체 순위 | MIT 모델을 고정 커밋으로 내려받아 오프라인 계산 |

- Web Share API를 지원하지 않는 브라우저에서는 같은 텍스트를 클립보드에 복사합니다.

- LGPL-3.0 공개 형태소 분석기 Kiwi를 데이터 빌드 단계에서만 사용해 활용형 별칭 577,999개를 만들었습니다.
- 동사·형용사는 Kiwi 결합기로 불규칙 활용을 포함한 자주 쓰는 표면형을 생성합니다.
- 명사 조사는 별칭 파일로 복제하지 않고 웹 서버가 표제어 품사를 확인해 처리합니다.
- 여러 기본형과 충돌하거나 사전 표제어와 같은 별칭은 제외해 잘못된 자동 변환을 줄입니다.
- 웹 서버는 미리 만든 활용형 별칭표와 명사 품사 정보만 사용하므로 요청마다 Python 분석기를 실행하지 않습니다.

### 2026-08-06 — 자동 회귀 테스트와 공개 CI

- Playwright가 데스크톱 Chrome과 Pixel 7 화면에서 추측, 별칭, 새로고침 복원을 검사합니다.
- API 회귀 테스트로 게임 메타와 추측 응답에 정답·퍼즐 ID가 노출되지 않는지 확인합니다.
- GitHub Actions가 Python 테스트와 Hugging Face 출처 검증, 웹 테스트·린트·빌드·E2E를 매 푸시마다 실행합니다.

### 2026-08-06 — 추측 결과 순위 정렬

- 추측과 힌트 결과를 입력 시점과 관계없이 정답에 가까운 순위부터 표시합니다.
- 정렬 과정에서 원래 추측 기록의 순서를 보존해 저장과 결과 공유 순서에는 영향을 주지 않습니다.

### 2026-08-06 — 현재 기록 기반 적응형 힌트

- 힌트를 요청할 때 현재까지 확인한 가장 높은 순위를 기준으로 사용합니다.
- 서버는 현재 최고 기록보다 숫자가 작은 순위의 단어만 반환하므로 힌트를 쓸 때마다 정답에 더 가까워집니다.
- 아직 추측이 없을 때는 전체 사전 순위 다음 값을 기준으로 첫 힌트를 계산합니다.

### 2026-08-06 — 게임 종료 후 전체 순위 공개

- 정답을 맞히거나 정답 공개를 선택한 응답에서만 오늘의 전체 280,804개 단어 순위를 제공합니다.
- 종료 화면의 `전체 순위 보기` 버튼으로 1위부터 마지막 순위까지 500개 단위로 탐색할 수 있습니다.
- 전체 순위는 브라우저 저장소에 복제하지 않으며, 새로고침 뒤 필요할 때 다시 불러옵니다.

### 2026-08-06 — 28만 단어 대규모 사전 확장

- Hugging Face의 NIKL 학습사전 전체와 표준국어대사전 변환본을 고정 리비전에서 병합했습니다.
- 조사·어미·접사와 기호가 섞인 항목을 제외하고, 동형어 뜻풀이를 합쳐 고유 표제어 280,804개를 만들었습니다.
- 모든 단어를 multilingual-e5-small로 다시 임베딩해 20개 퍼즐의 1위부터 280,804위까지 재계산했습니다.
- 전체 순위와 퍼즐을 서버 메모리에 캐시하고 화면에는 한 번에 500행만 렌더링해 대규모 데이터에서도 탐색할 수 있게 했습니다.

### 2026-08-06 — 사실상 무제한 시드 게임

- 20개 고정 퍼즐과 일일 일정을 제거하고, 0부터 4,294,967,295까지의 시드가 전체 280,804개 표제어 중 정답을 결정하도록 변경했습니다.
- 정규화된 임베딩을 8비트 정수로 양자화해 50,000단어 단위 파일로 분할했습니다. 서버는 선택된 정답과 모든 단어의 내적을 계산해 해당 시드의 전체 순위를 만듭니다.
- 동일한 `시드 + 게임 데이터 버전`은 항상 동일한 정답과 순위를 반환합니다. 데이터가 바뀌면 버전을 올려 기존 게임 주소의 의미가 조용히 바뀌지 않게 합니다.
- 주소의 `?seed=123&v=1`을 그대로 공유할 수 있고, 시드를 직접 입력하거나 암호학적 난수로 새 게임을 즉시 시작할 수 있습니다.
- 브라우저 기록은 날짜가 아닌 시드와 버전별로 분리해 저장합니다.
- 순위 계산 결과는 최근 4개 시드만 서버 메모리에 보관해 장시간 실행해도 캐시가 끝없이 늘어나지 않습니다.

## 로컬 실행

### 1. 데이터 파이프라인

```powershell
cd pipeline
uv sync --extra dev
uv run verify-sources
uv run build-demo-data
uv run pytest
```

첫 실행에서는 Hugging Face Hub에서 공개 사전과 모델을 내려받습니다. 전체 28만 단어 임베딩 재생성은 CPU 환경에서 수십 분이 걸릴 수 있습니다.

### 2. 웹앱

데모 데이터가 저장소에 포함되어 있으므로 웹앱만 바로 실행할 수도 있습니다.

```powershell
cd apps/web
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 시드가 없는 주소는 자동으로 랜덤 시드를 만들며, 예를 들어 `http://localhost:3000/?seed=123&v=1`은 언제 열어도 같은 문제입니다.

### 3. Expo Go로 모바일 앱 실행

PC와 스마트폰을 같은 Wi-Fi에 연결합니다. 먼저 `ipconfig`에서 Wi-Fi 어댑터의 IPv4 주소를 확인합니다. 예를 들어 PC 주소가 `192.168.0.10`이면 API 서버를 외부 기기에서 접근할 수 있게 실행합니다.

```powershell
cd apps/web
npm install
npm run dev -- --hostname 0.0.0.0
```

새 PowerShell 창에서 모바일 환경 파일을 만들고 주소를 실제 PC IPv4로 바꿉니다.

```powershell
cd apps/mobile
Copy-Item .env.example .env
```

```dotenv
EXPO_PUBLIC_API_BASE_URL=http://192.168.0.10:3000
EXPO_PUBLIC_SHARE_BASE_URL=http://192.168.0.10:3000
```

이후 Expo 개발 서버를 시작하고 Android의 Expo Go로 QR 코드를 읽습니다.

```powershell
npm install
npm start -- --lan
```

스마트폰에서 `localhost`는 PC가 아니라 스마트폰 자신을 뜻하므로 사용할 수 없습니다. Windows 방화벽 알림이 뜨면 신뢰하는 개인 네트워크에서만 Node.js 접근을 허용합니다. 자세한 확인 항목은 [`docs/mobile/ANDROID_TEST_CHECKLIST.md`](docs/mobile/ANDROID_TEST_CHECKLIST.md)에 있습니다.

## 현재 한계

- 시드는 약 42억 개지만 정답 후보는 사전에 포함된 280,804개이므로 서로 다른 시드가 같은 정답을 고를 수 있습니다.
- 뜻풀이 임베딩은 다의어의 여러 의미를 하나로 합치므로 일부 순위가 직관적이지 않을 수 있습니다.
- 표준국어대사전 기반 전문어까지 포함하지만 최신 신조어와 일부 고유명사는 인식하지 못할 수 있습니다.
- 연속 플레이 기록, 서버 분석, 신고 기능은 개인정보 수집을 피하기 위해 MVP에서 제외했습니다.
- 모바일 앱은 사전과 임베딩을 기기에 넣지 않으므로 게임 플레이에 API 서버 연결이 필요합니다.
- 현재 공유 URL은 `EXPO_PUBLIC_SHARE_BASE_URL` 설정을 사용합니다. 다른 사람이 열 수 있게 하려면 Play 배포 전에 공개 HTTPS 웹 주소를 지정해야 합니다.
